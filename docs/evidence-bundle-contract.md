# Source evidence contracts (v0.4 foundation)

This additive contract layer leaves the v0.3.9 Massive acquisition schema and sealer unchanged. A generalized source manifest records immutable source identity (`source_id`, provider, runtime, transport, adapter and capability versions), separate discovery, availability, qualification and admissibility states, source status/degradation reason, and dataset-level evidence role, digest, observation time, freshness bound, pagination and qualification/admissibility. The source identity digest matches the configured registry entry; a manifest ID is `sm-` plus the first 24 lowercase hex characters of SHA-256 over canonical manifest content excluding `manifest_id` and `content_digest`. A research input is valid only for a discovered, available, qualified and admitted source and complete dataset with complete pagination. `observed_at`, and present `published_at`/`available_at`, must be timezone-aware and precede the exclusive UTC `research_cutoff`; `max_age_seconds` bounds staleness at that cutoff.

Manifest `content_digest` is SHA-256 over UTF-8 canonical JSON (`sort_keys`, compact separators, ensure_ascii false), excluding only `content_digest`. Bundle ID is `eb-` plus the first 24 lowercase hex characters of SHA-256 over canonical `{schema_version,run_id,attempt_id,research_cutoff,members}`; bundle `content_digest` uses the same canonical JSON rule, excluding only `content_digest`. Bundle members are sorted by `source_id` when built and hold only a repository-root-relative manifest path, source and manifest IDs, and the source manifest digest/status; dataset payloads remain in source-owned artifacts. The verifier resolves paths beneath the declared root and checks bundle ID, manifest digest, source identity, run/attempt and cutoff bindings. Bundle membership records states; it does not promote them and does not mean every source is COMPLETE.

`config/source-registry.json` identifies the existing Massive MCP route as an identity reference only. It does not qualify or admit Massive evidence and does not alter the legacy daily workflow. A future compatibility bridge must reference, never rewrite, a legacy manifest and its original digest.

Fin Data source manifests use canonical source ID `fin_data_mcp_render_prod` and retain the provider-native MCP result digest and native rows alongside deterministic normalized JSONL. `scripts/control_plane/fin_data_source.py verify` checks the raw/normalized artifacts before their manifest is passed to `build_evidence_bundle.py`. The qualification report binds the configured endpoint, observed endpoint, Render deployment identity, MCP/tool response snapshot, and capability-policy digest. No Fin Data manifest may contain `RESEARCH_INPUT` unless the endpoint-bound qualification passes, the response/freshness contract is registered, and the separate source admission policy explicitly allows that capability. Unknown endpoint availability yields a `BLOCKED` manifest/report; known cold/unavailable endpoint yields `UNAVAILABLE`; neither state authorizes fallback.
