# Source evidence contracts (v0.4 foundation)

This additive contract layer leaves the v0.3.9 Massive acquisition schema and sealer unchanged. A generalized source manifest records immutable source identity (`source_id`, provider, runtime, transport, adapter and capability versions), separate discovery, availability, qualification and admissibility states, source status/degradation reason, and dataset-level evidence role, digest, observation time, freshness bound, pagination and qualification/admissibility. A research input is valid only for a qualified and admitted source and dataset. `observed_at` must precede the exclusive UTC `research_cutoff`; `max_age_seconds` bounds staleness at that cutoff.

Manifest `content_digest` is SHA-256 over UTF-8 canonical JSON (`sort_keys`, compact separators, ensure_ascii false), excluding only `content_digest`. Bundle digest uses the same rule. Bundle members are sorted by `source_id` when built and hold only a repository-root-relative manifest path, source and manifest IDs, and the source manifest digest/status; dataset payloads remain in source-owned artifacts. The verifier resolves paths beneath the declared root and checks manifest digest, source identity, run/attempt and cutoff bindings. Bundle membership records states; it does not promote them and does not mean every source is COMPLETE.

`config/source-registry.json` identifies the existing Massive MCP route as an identity reference only. It does not qualify or admit Massive evidence and does not alter the legacy daily workflow. A future compatibility bridge must reference, never rewrite, a legacy manifest and its original digest.
